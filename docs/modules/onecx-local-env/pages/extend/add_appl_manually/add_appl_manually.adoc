= Add an Application Manually to OneCX

When you have created a custom application and want to run it in the OneCX local environment, you need to add the application to the OneCX. This involves adding the application to the product store, adding the application to the workspace, and assigning permissions and roles for accessing the application.

This guide is created for webpack module apps. To see all supported types of microservices, see the {onecx_docs_overview_mfe_ref} documentation.

Alternatively you can use `local-env-cli` to add your application to the OneCX local environment. See {onecx_local_env_cli_ref} for more details.


== Prerequisites
Before you can add your custom application to the OneCX, you need to have the following prerequisites in place:

* Your UI app needs to have webpack module federation implemented. See the {onecx_docs_overview_mf_ref} documentation for details on how to implement webpack module federation in your application. 

* You have to add the xref:onecx-local-env:extend/local-mfe.adoc[micro frontend] to the OneCX local environment using `./toggle-mfe` script.


== Guide Steps

. xref:./add_appl_to_workspace.adoc[Register the application in the Workspace]
. xref:./add_permissions.adoc[Assign permissions and roles (Optional)]


[NOTE]
====
Like all manual changes in the local environment, manually created applications will be lost when the Postgres volume is deleted (e.g. by running `./stop-onecx.sh -c`).
