= Mocking in OneCX

Mocking is a software development and testing technique in which real system dependencies are replaced with controlled, simulated components. This allows teams to develop and test applications in isolation without relying on live backends or external services. +
The three key components of mocking are:

Mock Data:: Artificially generated sample data (e.g., fake names or prices) that simulates realistic content for testing and development.
Mock API:: A simulated programming interface that returns predefined responses (usually mock data) to requests without real backend logic.
Mock Server:: The running server instance in the background that hosts one or more mock APIs and handles real HTTP requests.

There are different ways to prepare Mock APIs. Here we use {node_js_link}.

== Using the Mock API
To use the Mock API for your generated UI app, you need to configure your app to point to the mock server's URL (e.g. \http://localhost:3000) instead of a real backend URL. Due to the generated UI app is a Webpack application, the generator has also created a `proxy.conf.js` file that configures the mapping of API paths to backend URLs. This file is located in the root directory of your Angular project.

[horizontal]
Directory:: `<root-of-ui-app>`
File::      `proxy.conf`

.Excerpt of the generated `proxy.conf` with the BFF URL
[source, javascript]
----
...
const PROXY_CONFIG = {
  '/bff': {
    target: 'http://bookstore-bff',
    secure: false,
    pathRewrite: { '^.*/bff': '' },
    changeOrigin: true,
    logLevel: 'debug',
    onProxyRes: onProxyRes
  }
}
----

Replace the real BFF URL `\http://bookstore-bff` with the Mock server URL `\http://localhost:3000`.

.Use the mock server URL as target URL of the BFF
[source, javascript]
----
...
const PROXY_CONFIG = {
  '/bff': {
    target: 'http://localhost:3000',
    secure: false,
    pathRewrite: { '^.*/bff': '' },
    changeOrigin: true,
    logLevel: 'debug',
    onProxyRes: onProxyRes
  }
}
----
